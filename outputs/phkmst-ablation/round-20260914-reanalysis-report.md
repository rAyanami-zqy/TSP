# PHKMST 消融实验重新分析（2026-09-14）

## 结论

P32 仍是当前 PHKMST 配置中总体最优且最可靠的方案，应继续作为默认配置。
`min-gap=0.005` 的门控配置能降低部分已解实例的运行时间，但所有变体的成功集合
都是 P32 成功集合的真子集，不能替代 P32。

## 数据完整性与分析口径

- 数据包含 1 组 Concorde 参考配置和 16 组 PHKMST 配置，每组 50 个实例，共 850 条记录。
- 所有运行均为 `complete`，没有缺失、重复或 `error`；每个配置、每个实例只有一次观测。
- 16 组 PHKMST 使用同一个求解器二进制指纹 `152b4d43...`。
- PHKMST 成功完成的 536 条记录全部与 Concorde 的最优费用一致。
- 536 条成功记录全部满足
  `候选数 = 触发数 + 各种跳过原因之和`。
- 排名首先比较成功数；为避免只统计成功实例造成幸存者偏差，同时给出：
  - 实际均值：超时按实际消耗的 1800 秒计入；
  - PAR-2：超时按 3600 秒计入。

## 成功集合分析

50 个实例中：

- 28 个被全部 16 种 PHKMST 配置解出；
- 10 个被全部 PHKMST 配置超时；
- 12 个实例真正区分了配置的求解能力。

P32 解出了全部 12 个区分性实例。其余每种配置的成功集合都是 P32 成功集合的真子集，
没有配置解出 P32 未解出的实例。`ch130`、`ch150` 和 `kroA150` 只有 P32 成功，
用时分别为 286.8 秒、120.1 秒和 183.4 秒。

P32 仍超时的实例为：`bier127`、`brg180`、`d198`、`kroB150`、`pr107`、
`pr136`、`pr152`、`qa194`、`si175`、`xqf131`。

## min-gap=0.005 的代价与收益

P32 与 `gap0.005-0.03` 共同成功 37 个实例；后者没有新增成功实例，并丢失
`ch130`、`ch150` 和 `kroA150`。在共同成功集合上：

| 指标 | P32 | gap0.005-0.03 | 变化 |
| --- | ---: | ---: | ---: |
| 总运行时间 | 3064.5s | 2412.0s | -21.3% |
| 分支数 | 4.55M | 188.74M | +4051% |
| 更新候选数 | 4.23M | 137.90M | +3163% |
| 实际触发更新 | 3.84M | 0.305M | -92.1% |
| 势迭代总数 | 42.32M | 8.27M | -80.5% |

门控的实质是减少昂贵的节点势优化，用约 41 倍的搜索树换取更便宜的单节点处理。
这种交换在部分实例上有效，但会使三个 P32 能解出的关键实例直接超时。

`gap0.005-0.03` 在共同集合上只赢得 16/37 个实例；总时间下降主要由 `pr76`、
`pr144` 和 `u159` 等少数重实例贡献，因此不能解释为普遍加速。

## max-gap 扫描

成功数随 max-gap 的变化为：

```text
0.010 -> 34
0.015 -> 35（新增 pr76）
0.020 -> 37（新增 pr144、rat195）
0.030 -> 37
0.040 -> 37
```

`[0.02, 0.04]` 是成功数平台，但不能称为搜索过程“完全中性”：

- `0.02 -> 0.03`：共同 37 个实例总时间下降 11.1%，分支下降 23.5%，
  实际触发更新下降 71.5%；
- `0.03 -> 0.04`：总时间增加 0.4%，分支增加 0.25%，在单次运行下可视为近似持平。

因此 `0.03` 是 `min-gap=0.005` 组中当前最有希望的点，但其成功率仍低于 P32。

## hk-update-iterations

在 `min-gap=0.01、max-gap=0.1` 下，32 和 64 次迭代的成功集合相同，均解出
35 个实例；64 次的成功实例总时间比 32 次低 27.9%，分支数低 19.4%。128 次
反而丢失 `u159`，只解出 34 个。因此 64 次比 32 次更值得复测，128 次不应保留。

在 `min-gap=0.05` 下，32/64/128 三个配置的实际更新触发数均为 0，成功集合和
分支数也与关闭节点更新相同。这里 iterations 没有效果，是因为门槛阻止了所有更新。

## 局限与后续实验

- 当前每个配置只有一次运行，不能给出运行时间置信区间。
- `workers=5` 会使 wall time 受到并发竞争影响。
- timeout 行没有分支数和更新计数，所有机制分析都以成功样本为条件。
- `summary.csv` 的 `total_wall_seconds` 只累计成功实例，字段名容易被误解为包含超时。
- `P33-2-55fad69d5115/configuration.csv` 的参数为 `min-gap=0.02`，但 description
  误写为 `gap>5%`；只影响标签，不影响实际运行参数。

建议下一轮：

1. 保持 P32 为默认配置；将 `gap0.005-0.03` 仅作为实验候选。
2. 增加 `min-gap=0、max-gap=0.03/0.04/0.1`，单独隔离 max-gap 的作用。
3. 测试 `min-gap=0.001/0.0025、max-gap=0.03`，寻找速度和完成率的折中。
4. 对领先配置至少重复三次，并使用更受控的并发方式。
5. timeout 时保存最终分支和节点势更新计数。
6. 优先覆盖 12 个区分性实例，减少简单实例对实验成本的占用。
