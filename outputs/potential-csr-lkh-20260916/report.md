# 节点势上升：压缩候选扫描、DSU 复用与临时 CSR

日期：2026-09-16。分支：`GAPMST`，基点 `8591420`。

## 改动

本实验只改变 `updateNodePotentialBound` 内部的数据准备与遍历方式，不改变
势更新的触发条件、Polyak 公式、停止条件、下界、epoch 安装或分支策略。

1. 生产 DFS 不再为每次节点势上升扫描完整的 `u<v` 距离矩阵，而是枚举当前
   compact candidate epoch 的 active 位；局部单元测试状态保留完整图兼容路径。
2. 没有 forced 根边时，直接复用 `PartialSol` 已维护的 forced DSU。存在
   forced 根边时，通用 DSU 会经过顶点 0 错误连接内部顶点，因此安全回退为
   只合并内部 forced 边的局部 DSU。
3. 本次上升使用的双向 Prim 邻接由 `head/next` 链改为连续的临时 CSR：
   `offsets[n+1] + arcs[2m]`。

## 配置与方法

固定使用本地隔离式 LKH provider 和当前 GAPMST 参数：

```text
--lkh-pi-mode warm-start
--root-pi-refine-iterations 16
--hk-ascent hybrid-reverse
--hk-node-ascent polyak
--branch-edge-order weight
--hk-potential-update subtree-adaptive
--hk-update-depth 1
--hk-update-gap-ratio 0.02
--hk-update-min-gap-ratio 0
--hk-update-min-gap-change-ratio 0.0001
--hk-update-gap-change-start-depth 2
--hk-update-iterations 32
--hk-update-budget 0
--root-candidate-compaction on
--exact-max-n 199
```

选择15个能够较快完成、同时覆盖无节点势更新到约14万次势迭代的实例。基线与
优化版各运行7次；奇偶轮交换二进制顺序，并反转实例顺序。两者使用完全相同的
LKH provider。


## 正确性

- C++/CLI CTest：10/10 通过，测试目标启用 `TSP_VERIFY_INCREMENTAL_STATE`；
- Python runner 测试：9/9 通过；
- 15实例、两种二进制、7轮全部返回 `ok`；
- 每个实例的 cost、根下界、候选边数、created、expanded、势更新候选数、
  触发数、gap-change 跳过数、改善/直接剪枝/重建/早停数和势迭代数完全一致；
- 因而本轮加速来自数据结构与扫描成本下降，而不是搜索树或启发式路径变化。

## 结论

组合优化有效，且收益随节点势工作量增加而变得明显。当前15实例结果支持保留
该实现：整批端到端时间下降约10.3%，节点势耗时下降约12.1%，同时保持所有
确定性搜索指标不变。后续若要进一步拆分贡献，可增加三个编译期开关分别消融
“压缩候选扫描”“DSU复用”和“CSR布局”；本轮先验证的是拟合生产路径的组合收益。

原始数据见 `raw_results.csv`，逐实例汇总见 `summary.csv`，逐轮数据见
`batch_results.csv`，总表见 `aggregate.csv`。
