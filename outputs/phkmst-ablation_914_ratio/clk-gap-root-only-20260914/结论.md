# Adaptive CLK gap ratio root-only 实验结论

## 实验范围

- 实例：`data/classic/batch-n200.txt` 中与既有消融报告一致的 50 个实例。
- 二进制：当前 CPHKMST Release 构建。
- 根策略：`--hk-ascent hybrid-reverse`。
- 每个配置、每个实例重复 3 次，时间取中位数。
- 所有配置均指定 `--root-bound-only`，只执行初始 tour、根势上升和根 1-tree。
- 未执行 root fixing、节点势更新、guarded warm start 或 BP 精确搜索。

主扫描共 8 个配置、1,200 次实例运行；另对 `0.014` 做了 450 次细化运行。

## 对当前默认 `0.02` 的回答

默认阈值触发 25/50 个实例，其中 18 个改善 UB，7 个触发后没有改善。它把 CLK starts 从固定 triple 的 150 降为 100。

45 个在 triple 下具有实质 root-only wall 增时的实例中：

- 24 个不再触发追加 CLK；
- 21 个仍会触发追加 CLK。

因此答案是：默认 `0.02` 已过滤掉约一半已确认的增时实例，但没有把它们全部过滤掉。

不再触发的 24 个实例：

```text
att48 bayg29 bays29 berlin52 brazil58 burma14 dantzig42 dj38
eil51 fri26 gr17 gr21 gr24 gr96 hk48 kroA150 lin105 pr124
pr144 rat99 si175 swiss42 ulysses16 wi29
```

仍然触发的 21 个实质增时实例：

```text
bier127 ch130 ch150 eil101 eil76 gr120 gr137 gr48 kroA100
kroB100 kroB150 kroC100 kroD100 pr107 pr136 pr152 pr76 qa194
rd100 st70 xqf131
```

默认 `0.02` 触发但没有改善 UB 的 7 个实例：

```text
kroA100 kroC100 pr107 pr152 pr76 qa194 rat195
```

默认 `0.02` 没触发、但 triple 能改善 UB 的 3 个实例：

| 实例 | single 根 gap | triple 的 UB 改善 |
|---|---:|---:|
| swiss42 | 0.158% | 1 |
| rat99 | 1.471% | 2 |
| gr96 | 1.845% | 184 |

其中 gr96 的 UB 改善较大，说明 2% 阈值并非没有质量代价。

## 为什么 adaptive 的 root-only 时间反而更长

当前流程是：

```text
single CLK
  → 第一次根势上升以取得 gap
  → 追加 CLK
  → 若 UB 改善，重新根势上升
```

所以 adaptive 虽然少做了 CLK，却可能做两次根势上升。默认 `0.02`：

- 初始 tour 总时间比 triple 少约 0.270 秒；
- 根势总时间比 triple 多约 2.520 秒；
- 最终 root-only wall 比 triple 多约 2.257 秒，比 single 多约 3.162 秒。

这不是 BP 搜索导致的，因为实验根本没有进入 BP。主要代价就是“为了判断是否追加而先计算一次根证书，UB 改善后又重新优化根势”。

## gap ratio 建议

### 如果目标是保留绝大多数可见 UB 改善

本批数据建议把下一候选阈值设为 `0.014`：

- 触发 29/50；
- 改善 20/50；
- 捕获 triple 的 20/21 个有益实例；
- 相比 `0.01` 少触发 2 个无改善实例；
- 相比 `0.015` 多保留 rat99 的一次改善；
- 唯一漏掉的是 swiss42 的 1 点 UB 改善。

这是“上界质量”意义上的推荐值，不是 root-only 时间最优值。

### 如果目标只是最小化根预处理时间

应使用 `--initial-clk single`。本实验 single 为 6.010 秒，快于 triple 和所有 adaptive 阈值。

若必须保留 adaptive，`0.05` 的时间接近 triple，但只保留 2/21 个 triple 有益实例，不建议直接作为精确求解默认值。

### 当前不建议直接修改生产默认值

完整求解中，更紧 UB 可能显著减少 BP 节点，root-only 无法衡量这部分收益。因此当前证据支持把 `0.014` 作为下一轮候选，但不足以证明它的最终 PAR2 优于 `0.02`。

## 下一步最小验证

如果仍坚持不跑完整 50 实例，可只对以下实例做限时对比：

- 边界有益：`rat99`、`gr96`、`eil76`、`st70`；
- 高 gap 无改善：`pr107`、`pr152`、`qa194`；
- 大 UB 改善：`bier127`、`gr137`、`pr136`。

只比较 `single / adaptive-0.014 / adaptive-0.02 / triple`，设置短超时并保存最终 UB、LB、gap 和节点数，即可判断额外根势成本是否能由搜索树缩减收回。
