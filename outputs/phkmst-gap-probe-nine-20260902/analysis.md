# 节点势两阶段 probe 与 gap 门实验（9 实例）

日期：2026-09-02。所有配置使用 Release 构建、单 worker、Polyak 根势与节点势、
`subtree-adaptive`、epoch 层距 2、最多 16 次 1-tree 评估、更新预算 5000。
每个配置/实例独立运行 5 次；下表是该实例 5 次外部墙钟时间的中位数，不是把
九个实例混在一起取中位数。225 次主实验和 90 次反序复核全部返回已知最优值，
无超时或错误。

## 策略定义

- `Gap2`：仅相对 gap 不超过 2% 时执行完整上升；
- `Gap5`：相对 gap 不超过 5% 时执行完整上升；
- `Probe1-x`：gap<=2% 直接跑满；2%<gap<=5% 时先执行 1 次势移动
  （起点和移动后共 2 次 1-tree 评估），coverage>=x 才继续；
- `Probe2-x`：相同 gap 门，但先执行 2 次势移动（共 3 次 1-tree 评估）。

coverage 为：

```text
max(0, probe_best_LB - original_LB) / (UB - original_LB)
```

拒绝时不安装 probe 的势或临时下界；该计算仍计入当前搜索轮的更新尝试预算。

## 结论

1. 两轮 probe 明确不划算，最佳阈值仍比现有 Gap2 慢 2.06%。
2. 一轮 probe 的信号很弱：第一步几乎总是没有改善，因此 1%--5% coverage 门
   实际产生相同决策。交错复核显示约 0.8% 的小幅加速，主要来自 `eil101`，
   但 created 反而比 Gap2 多 2.54%。
3. 这不足以替换 Gap2 默认策略。实现保持默认关闭，适合继续作为实验开关；若
   扩展样本后仍要研究，重点应是判断“第一步是否改善”，而不是精调 1%--5%
   的 coverage 数值。
