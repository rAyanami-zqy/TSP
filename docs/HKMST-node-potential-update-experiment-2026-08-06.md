# HKMST 搜索节点势更新实验

> 本文记录第一阶段的“临时下界证书”实验。随后已经实现让更新势在完整
> 子树中持续生效的势 epoch，见
> [HKMST 持久子树势更新实验](HKMST-persistent-potential-epoch-experiment-2026-08-06.md)。

## 结论

“势更新”值得继续保留，而且当前最有效的不是在较深层定期更新，而是：

```text
adaptive，最小深度 1，相对 gap <= 1%，每次最多 16 轮，正式 DFS 每轮预算 5000
```

在此前根上升实验的 9 个可完整求解实例上，它保持全部已知最优值不变，
创建节点由 2,600,206 降至 451,299（-82.64%），展开节点由 1,911,618
降至 301,613（-84.22%）。本机整批单次 wall time 从 3.56 s 降至 1.83 s
（-48.60%）。默认仍保持 `none`，因为目前样本规模有限，且节点更新使用
O(k n^2 log n) 的独立重算，尚未做候选排序缓存。

## 实现边界

根节点仍按 `--hk-ascent` 计算一组全局势。搜索节点触发更新时：

1. 从根势 warm start；
2. 在当前 forced、forbidden 和 active candidate 约束下重算固定根 1-tree；
3. 运行有限轮 Polyak 更新；
4. 只保存该节点得到的更强下界；
5. 若新下界达到 incumbent，直接剪枝；否则继续使用原 HKMST 1-tree 分支。

节点更新不会写回 `vertex_potential_`，也不会改变 `candidates_sorted_`、
`root_candidates_sorted_`、forced-edge 权重缓存或 dynamic-MST replacement。
因此它是“额外下界证书”，不是子树 HKMST 的全量换势。这一边界避免了
兄弟节点之间全局排序和增量状态失效，适合先验证势更新本身的收益。

临时势 `pi` 下的节点下界仍为：

```text
min constrained 1-tree sum(c(i,j)+pi[i]+pi[j]) - 2*sum(pi) - roundoff_guard
```

## 触发策略

| 策略 | 条件 |
|---|---|
| `none` | 默认；搜索节点不更新 |
| `depth` | `depth > 0` 且 `depth % interval == 0` |
| `adaptive` | 达到最小深度、度数违规非零，并且 `(UB-LB)/max(1,abs(UB)) <= ratio` |

两种更新策略都有每次最大迭代数和每轮尝试预算。预算在 incumbent 改善并
重启固定根势 DFS 时清零。初始 DFS 同时承担 diversified-LK 困难度探测；
该轮可能被回滚，所以自动把预算封顶 1000，探测结束或重启后再开放用户预算。

## 深度扫描

共同参数为每次 8 轮、每轮预算 1000。实例为 dantzig42、att48、bayg29、
bays29、st70、rat99。

| 深度策略 | created | expanded | 相对 baseline expanded |
|---|---:|---:|---:|
| baseline / `none` | 227,162 | 159,534 | - |
| interval 1 | 183,726 | 126,513 | -20.70% |
| interval 2 | 188,211 | 130,456 | -18.23% |
| interval 4 | 205,348 | 142,823 | -10.47% |
| interval 8 | 214,297 | 149,454 | -6.32% |

越深的节点单次更新越容易直接跨过剪枝阈值，但介入太晚；浅层更新对整个
后续子树生效，综合收益明显更大。因此 `depth=1` 适合作为 adaptive 的最小深度。

## gap 与迭代数

gap 阈值扫描表明 0.5% 太保守，许多有价值的节点直到很深才触发；2% 与
所有浅层节点更新接近。1% 在本组实例上取得更好的开销/覆盖折中。

`rat99` 对每次迭代数最敏感：

| 最大迭代数 | created | expanded | 势更新时间 |
|---:|---:|---:|---:|
| baseline | 49,944 | 37,385 | 0 |
| 2 | 49,560 | 36,741 | 0.034 s |
| 4 | 36,367 | 26,718 | 0.067 s |
| 8 | 7,100 | 4,698 | 0.104 s |
| 16 | 1,050 | 269 | 0.126 s |
| 32 | 964 | 243 | 0.156 s |

16 到 32 轮只少展开 26 个节点，更新时间继续增加，所以推荐 16。

## 9 个经典实例结果

更新参数：adaptive、最小深度 1、gap 1%、16 轮、正式轮预算 5000。

| 实例 | baseline created/expanded | 更新后 created/expanded | attempts | update-pruned | update time |
|---|---:|---:|---:|---:|---:|
| st70 | 176651 / 121714 | 150367 / 100238 | 1631 | 1421 | 0.097 s |
| eil76 | 162489 / 121189 | 136397 / 100033 | 1059 | 1028 | 0.027 s |
| rat99 | 49944 / 37385 | 1050 / 269 | 816 | 653 | 0.126 s |
| eil101 | 2210554 / 1630895 | 163409 / 101048 | 4735 | 3689 | 0.657 s |

| att48 | 538 / 414 | 59 / 20 | 55 | 36 | 0.002 s |
| bayg29 | 3 / 3 | 3 / 1 | 2 | 2 | <0.001 s |

| **合计** | **2600206 / 1911618** | **451299 / 301613** | **8307** | **6836** | **0.909 s** |

表中的合计更新时间使用同参数运行的逐例统计近似值；加入探测轮封顶后，
最终整批 wall time 为 1.83 s。节点数是确定性指标，计时仅是本机单次诊断。

`eil101` 的预算扫描说明预算确实是有效旋钮：预算 1000、2000、5000 时，
展开节点分别为 1,076,453、687,245、101,048；5000 后正式搜索在用满预算前
已经结束。本组推荐值因此取 5000，但不据此直接改成全局默认。

## 使用方式

```sh
./build/tsp_bb --hk-ascent polyak \
  --hk-potential-update adaptive \
  --hk-update-depth 1 \
  --hk-update-gap-ratio 0.01 \
  --hk-update-iterations 16 \
  --hk-update-budget 5000 \
  data/classic/tsplib/eil101.tsp
```

批处理 CSV 与单实例输出新增：attempted、improved、update-pruned、迭代数、
更新时间、总下界增益和最大单次增益。

## 正确性验证

- Release CTest 4/4 通过；
- depth/adaptive 都在 dantzig42 上返回已知最优值 699，并实际触发改善和剪枝；
- 额外使用 6 点实例的独立穷举最优值验证零根势下的节点更新证书；
- 8 个完整随机图和 8 个稀疏随机图在零根势 + adaptive 更新下均与独立穷举一致；
- 极端动态范围实例会自动禁用节点势更新，并保持原精确结果；
- 9 个经典实例全部返回与 baseline 相同的已知最优值；
- 每次临时下界都扣除按临时势尺度计算的浮点 roundoff guard。

## 后续进展

本文最后提出的“让更新势真正写入完整子树”已经完成：在选中锚点保存父
epoch，安装更新势，重建候选顺序、edge rank、active bitset、可用度数、
forced-edge 权重缓存和 1-tree，再用新状态搜索整个子树；退出时完整恢复。
九实例上该实现比本文证书模式更快，并可通过更宽的 gap 门槛进一步减少
搜索节点。实现和新一轮参数扫描单独记录在持久子树势更新实验文档中。
