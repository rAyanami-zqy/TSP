# CPHKMST 初步实验（2026-09-09）

## 改动

本分支组合验证三项可直接迁移的 Concorde 风格预处理思路：

1. 初始上界使用三个 NN+2-opt 起点做 chained LK；原最佳起点保留旧的固定
   double-bridge 轨迹，另外两个起点使用确定性多样化 kick，避免新增探索使原
   单起点结果退化。
2. k-nearest 与启发式 tour 边组成稀疏提示图。动态 MST replacement 先在提示图
   找候选上界，但仍对该上界之前的完整 active fundamental cut 做精确证明；
   未找到提示时扫描完整割集，所以不改变精确搜索可行域。
3. 导出根 reduced-cost fixing 的调用次数、测试数、固定为 0/1 的边数、剩余
   active 边数与耗时，并接入人类可读输出、批处理 CSV 和 PHKMST 消融运行器。

没有迁移 Concorde 依赖 LP reduced cost 的完整 edge elimination，因为当前实现
没有等价 LP relaxation/certificate；直接照搬会破坏精确性。

## 方法

- 基线：`0e31367`（分支创建前的 PHKMST），Release 构建。
- 候选：CPHKMST，Release 构建。
- 数据：`data/classic/batch-node-ascent.txt` 中 9 个 TSPLIB 实例。
- 参数：`--hk-ascent polyak --hk-node-ascent polyak --branch-edge-order weight
  --hk-potential-update subtree-adaptive --hk-update-depth 1
  --hk-update-gap-ratio 0.02 --hk-update-min-gap-ratio 0.0
  --hk-update-iterations 32 --hk-update-budget 0 --exact-max-n 130`。
- 同一机器顺序执行；完整基线一次、候选两次，另单独复测基线 `eil101`。

- 9/9 实例的最终精确最优值与基线一致。
- 创建节点合计下降 97.73%，实例时间合计下降 97.65%。

## 结论与限制

组合改动在这组初测上有明确正向提升，核心原因是更紧初始 UB 改变了根势上升
和后续搜索轨迹：`eil101` 的 UB 从 646 降到 638，创建节点从 79679 降到 634。
`st70`、`rat99` 也得到正收益。

收益并非逐实例单调：`eil76` 虽然 UB 改善 1，但搜索轨迹变差；已经很容易的实例
则主要承受三个 LK 起点的固定开销。因此当前证据支持继续扩大实验，但还不足以
断言对完整 50 实例集稳定占优。下一阶段应在相同负载下做交错重复，并分别关闭
“多起点 LK”和“稀疏 replacement 提示”以归因收益与回退。
