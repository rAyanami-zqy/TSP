# 07-14-deg 与 07-26-MST 版本差异及优化行为详解

## 1. 结论

`07-26-MST` 是 `07-14-deg` 的同一条精确 MST/1-tree 求解路线经过两类优化
后的版本：

1. **不改变搜索树语义的热路径优化**
   - 候选集由逐层复制改成 active bitset + undo；
   - OneTree 由逐层复制改成单棵可变树 + undo；
   - MST replacement 改用动态树拓扑、fundamental cut 位图和 O(1)
     边索引；
   - forced DSU、候选过滤、available degree 和短 BP 集均增加专用快速路径。
2. **有严格证明、会缩小逻辑搜索树的传播优化**
   - 根 1-tree 树边 reduced-cost fixing；
   - BP singleton `x_e=1` 传播。

因此不能再把两者概括为“算法完全相同，只是 07-26 常数更小”：

- degree 分支、受约束 1-tree、BP 分区和 DFS 分支定界框架仍然相同；
- 07-26 除了降低每个状态转换的成本，还会通过 singleton 传播消除必然只有
  一个孩子的逻辑节点；
- 根树边 fixing 在命中时还会永久缩小根候选集。

按 `docs/comparison-cache.json` 中 `tsp_bb_26_07_14_deg` 与
`tsp_bb_07-26-MST` 共同完成的 10 个实例汇总：

| 指标 | 07-14-deg | 07-26-MST | 07-26 相对变化 |
|---|---:|---:|---:|
| 总耗时 | 549.2720 s | 104.7672 s | **-80.93%** |
| Expanded | 52,355,436 | 42,443,250 | **-18.93%** |
| Created | 96,607,625 | 68,112,391 | **-29.50%** |

总耗时会被 `bays29` 等长实例显著加权，不能解释为任意实例都固定快 80.93%；
逐实例结果见第 21 节。

## 4. 保持不变的算法骨架

### 4.1 degree 分支策略

两个版本都会：

1. 在当前 1-tree 中寻找度数大于 2 的违规顶点；
2. 选择度数最大的违规顶点；
3. 从该顶点关联的未决树边中选取最轻边；
4. 用该边继续构造 BP 的关键边集合 `B`。

`07-26-MST` 没有改成 `min_edge` 配置。`min_edge` 仍由
`TSP_BRANCH_STRATEGY_MIN_EDGE` 控制，是另一条历史实验配置。

### 4.2 受约束 1-tree

两者的 1-tree 都由：

- 顶点 `1..n-1` 上受 `forced` / `forbidden` 约束的 MST；
- 顶点 `0` 的两条最轻合法关联边；
- 共 `n` 条边的成本和；

组成。若每个顶点的 degree 都等于 2，该 1-tree 就是一条 Hamilton 回路。

### 4.3 BP 多路分支

若 BP 得到：

```text
B = [B0, B1, ..., Bk-1]
```

基本分区仍是：

```text
force B0
forbid B0, force B1
forbid B0..B1, force B2
...
forbid B0..Bk-2, force Bk-1
```

全部 `B` 边均 forbidden 的区域已经被 BP 终止条件证明不可能严格改善
incumbent，因此不生成额外孩子。

## 5. 总体状态模型：复制改为 checkpoint/undo

### 5.1 07-14-deg

一次子节点展开大致为：

```text
复制 prefix_candidates
  -> 复制 child_candidates
  -> 全量扫描并压缩候选 vector
  -> 重算所有顶点 available degree
  -> 复制 prefix_tree 得到 child_tree
  -> 对失效边做 replacement
  -> 递归
  -> 恢复 candidate_mask、forced DSU 和 degree
```

稠密图的候选数可达 O(n²)。即使只 force 一条边，也可能复制和扫描整个候选
数组。

### 5.2 07-26-MST

对应流程变为：

```text
记录 candidate/tree checkpoint
  -> 原地 force 并更新可回滚 DSU
  -> 只停用新近失效的 active candidates
  -> 只替换当前 OneTree 中真正失效的树边
  -> 在同一棵 OneTree 上递归
  -> rollback tree
  -> rollback candidates
  -> rollback forced 状态
```

正常热路径只记录本层 delta；只有增量修复失败时才保存完整 OneTree 快照。

## 6. 优化一：移除生产路径的冗余完整验证

### 07-14 行为

`oneTreeSatisfiesConstraints()` 会在进入节点、forbid replacement、force
replacement 和 rebuild 后频繁检查：

- 边数、根边数和 degree；
- forced 边是否全部存在；
- forbidden 边是否意外存在；
- cost 缓存是否与边集合一致；
- 内部 MST 结构是否正确。

该验证适合测试，但每个节点执行会重复遍历整棵树。

### 07-26 行为

- 生产构建信任已经验证的局部增量操作；
- replacement 明确失败时，回滚并执行完整 `computeOneTree()`；
- `TSP_VERIFY_INCREMENTAL_STATE` 构建仍会完整重建并对比可行性、成本和所有
  镜像状态。

`98fda95` 的单实例记录显示，当时 `burma14` 约改善 42%。该数值是独立提交的
历史测量，不能与其他百分比相加。

## 7. 优化二：OneTree 边位置 O(1) 索引

### 07-14 行为

边被 forbid 或停用后，用：

```cpp
std::find_if(tree.edges.begin(), tree.edges.end(), ...)
```

在约 `n` 条 OneTree 边中搜索其位置。

### 07-26 行为

OneTree 维护：

```text
edge_index_in_tree[edgeId(u,v)]
```

- `-1` 表示边不在树中；
- 非负值表示 `tree.edges` 下标。

构建、replacement 和 rollback 都同步更新该表。

### 收益和代价

- 查询从 O(n) 降为 O(1)；
- `c1b8387` 的 `burma14` 记录显示，当时 wall time 从 36.1 ms 降至
  29.7 ms；
- 代价是增加 O(n²) 整数索引，因此后续必须避免复制整棵 OneTree。

## 8. 优化三：动态 MST 邻接位图

### 07-14 行为

删除一条内部 MST 边时：

1. 新建临时 DSU；
2. 遍历除待删边外的内部树边；
3. 重建删除边后的两个分量；
4. 扫描候选寻找跨 cut 的最轻合法边。

每条失效树边都会重复重建一次 DSU。

### 07-26 行为

OneTree 维护内部 MST 的 `mst_adjacency_bits`。replacement 时：

1. 在遍历中忽略待删边；
2. 从待删边两端确定删除后的 component；
3. 用该 component 生成 fundamental cut；
4. 找到最轻 active crossing edge；
5. 同步执行 `cut(old)`、`link(new)`。

顶点 `0` 的两条根边不进入内部 MST 位图。根边失效时直接从
`root_candidates_sorted_` 选择下一条最轻合法边。

## 9. 优化四：从单向 component 遍历到较小分量双向遍历

### 07-20 阶段

最初的动态 MST 版本从被删边一端 DFS，标记完整一侧分量。若选中的一侧恰好是
较大分量，就会进行更多顶点访问，并在生成 cut candidates 时处理更多 incident
位图。

### 07-26 行为

`fe2b166` 开始从被删边两个端点交替扩展：

```text
left frontier  从 u 开始
right frontier 从 v 开始
```

某一侧先完成时，它必然是不大于另一侧的 component。程序只保留该较小分量，
供后续 cut 查询使用。

通用路径使用：

- 两组 component vector；
- 两个 epoch；
- 复用的 component mark。

这样既避免每次清零 O(n) 标记数组，也减少生成 fundamental cut 时处理的顶点数。

## 10. 优化五：fundamental cut candidate 位图

### 旧行为

确定一个 MST component 后，旧 replacement 路径按权重顺序逐条读取 active
候选，再分别查询两个端点是否位于 component 的不同侧。

### 07-26 行为

每个顶点已有不可变 incident candidate 位图。对选中的 component `S`，程序执行：

```text
cut_candidates = XOR(incident_bits[v]) for v in S
```

一条内部边：

- 两端都在 `S` 中时出现两次，XOR 后消失；
- 两端都不在 `S` 中时不会出现；
- 恰好一个端点在 `S` 中时出现一次，保留下来。

随后计算：

```text
cut_candidates
  & active_candidate_bits
  & internal_candidate_bits
```

得到当前合法的内部 crossing candidates。候选下标本身按权重排列，因此最低
置位下标就是最轻 replacement。

这把大量“逐候选端点 membership 检查”改成 machine-word 位运算。

## 11. 优化六：全局稳定候选表与 bitset-only active 状态

### 07-14 行为

- 候选 `std::vector<Edge>` 随递归复制；
- `buildBranchCandidates()` 全量 compact；
- BP 前缀用 `find_if + erase`；
- 每层恢复 candidate mask。

### 07-20 中间行为

07-20 先引入：

- 单份 `candidates_sorted_`；
- `candidate_mask`；
- active bitset；
- active 双向链；
- `edge_rank_by_id_`；
- CandidateUndo。

### 07-26 最终行为

`fe2b166` 进一步删除生产路径的 active 双向链和 O(n²) candidate mask 随机写，
以 `candidate_bits` 作为生产 DFS 的唯一 active 状态：

- 顺序枚举用“查找下一个置位 bit”；
- incident 过滤用位图交集；
- MST cut replacement 直接消费位图；
- CandidateUndo 只需记录稳定 candidate index。

`candidate_mask` 仅保留给局部候选 vector 和测试兼容路径。

这种统一减少了：

- active 状态的重复表示；
- 链表 previous/next 写入；
- 每次删除对 O(n²) mask 的随机内存写；
- undo record 大小。

## 12. 优化七：候选批量停用和回滚

### 单边停用

停用候选 index 时：

1. 清除 active bit；
2. 更新两个端点 available degree；
3. 把稳定 index 写入 `candidate_undo_`。

### 批量停用

当一个 word 中有多条候选需要失效时：

```text
removed = requested_bits & active_bits[word]
active_bits[word] &= ~removed
```

再使用尾零计数逐个记录实际被删除的 index。已在祖先节点失效的 bit 不会产生
重复 undo。

### 回滚

进入子节点前保存：

```text
candidate_checkpoint = candidate_undo_.size()
```

返回时逆序恢复 checkpoint 之后的 bit，并同步恢复 available degree。成本与本层
实际删除候选数成正比，而不是与全体候选数成正比。

## 13. 优化八：active incident 位图与批量度数更新

当顶点 `v` 的 forced degree 达到 2 时，它的其他 optional incident edges 必须
全部停用。

07-26 使用：

```text
removed_bits = active_bits & incident_bits[v]
```

只枚举当前仍 active 的关联边，不扫描已经失效的静态下标。

后续快速路径还会：

- 先按 word 批量清除这些 bit；
- `v` 自身的 available degree 一次性扣除删除数量；
- 各条边另一端的 available degree 和 undo 仍逐边维护。

这样避免对同一个 `v` 反复调用通用的单边 degree 更新。

## 14. 优化九：可回滚 forced DSU 成员集合

### 07-14 行为

force 边后，为全部顶点重新找 DSU root，再扫描全部候选，删除会在未覆盖全图的
forced component 内形成子回路的边。

### 通用 07-20/07-26 路径

每个 DSU root 保存 `forced_members`：

- union 时把败方成员追加到胜方；
- 记录胜方旧长度；
- rollback 时 resize；
- 只扫描本次合并前较小 component 的 active incident edges。

只有本次 union 后新落入同一 component 的边可能“新变成”子回路边，因此不需要
重扫全体候选。

### `n <= 64` 快速路径

07-26 为每个 DSU root 使用一个 `uint64_t`：

```text
forced_member_bits[root]
```

- union：bitwise OR，O(1)；
- rollback：恢复旧 word，O(1)；
- component 大小：popcount；
- 枚举较小 component：反复取最低置位 bit；
- 判断另一端是否同 component：单次 bit test。

`n > 64` 仍走 vector 成员列表的通用路径，保证规模兼容性。

## 15. 优化十：available degree 增量缓存

定义：

```text
available_degree[v]
  = forced_degree[v]
  + 当前 active optional incident edge 数
```

若该值小于 2，任何后代都无法使顶点达到 TSP 回路要求的 degree 2。

### 07-14 行为

每次候选过滤后：

1. 复制 forced degree；
2. 扫描全部剩余候选；
3. 累加每个端点；
4. 扫描全部顶点寻找 `< 2`。

### 07-26 行为

每次 force、candidate deactivate 和 rollback 时局部更新两个端点，并维护：

```text
insufficient_degree_count_
```

只有某顶点跨越 `< 2` 阈值时才修改计数。节点可行性检查最终为 O(1)：

```text
insufficient_degree_count_ == 0
```

## 16. 优化十一：只修复当前树中真正失效的边

### 07-14 行为

候选过滤生成所有 `removed_edge_ids`。其中可能有 O(n²) 条，但 OneTree 只有
`n` 条边。旧路径逐条查询每个 removed candidate 是否在树中。

### 07-20 行为

扫描当前 OneTree 的 `n` 条边，只收集其中 inactive 且非 forced 的边，再按全局
candidate rank 执行 replacement。

### 07-26 自适应行为

07-26 同时知道：

- 本层 CandidateUndo delta 数量；
- 当前 OneTree 边数。

因此：

- 若本层只删除很少候选，直接检查 undo delta；
- 若删除候选较多，再扫描完整 OneTree。

选择较小工作集合，避免固定采用某一种扫描方向。

## 17. 优化十二：单棵可变 OneTree 与 TreeUndo

### 07-14 行为

每个子节点复制 `prefix_tree` 和 `child_tree`。加入 O(n²)
`edge_index_in_tree` 和 MST adjacency 后，继续复制的成本会进一步放大。

### 07-26 行为

DFS 把同一棵 `OneTree&` 传给子节点。每次 replacement 的 TreeUndo 保存：

- tree edge index；
- old edge；
- new edge；
- old cost；
- old feasible。

交换与回滚同步维护：

```text
edges
degree
cost
edge_index_in_tree
mst_adjacency_bits
```

回滚直接恢复保存的 `old_cost`，而不是用反向浮点加减，避免 sibling 之间积累舍入
漂移。

增量失败并完整 rebuild 时才把旧 OneTree 移入 snapshot undo；这是冷路径。

## 18. 优化十三：BP 短集合内联存储与前缀重放

### BranchSet 内联

运行数据表明，大多数 BP 集只有 1～4 项。07-26 的 `BranchSet` 内含 4 个
`BranchChoice`：

- `|B| <= 4`：直接写入对象内部，不做 heap allocation；
- `|B| > 4`：才转移到 overflow vector。

这减少每个 expanded node 构造短 BP 集时的分配成本。

### 前缀 replacement 重放

`bpPartition()` 测试 `forbid B[i]` 时记录：

- 树边位置；
- replacement edge；
- 是否能直接 replay；
- 是否需要完整 rebuild。

枚举下一个前缀 sibling 时按需重放该 delta，不复制整棵前缀树，也不再次执行
同一 replacement 搜索。

07-26 还直接从 `BranchSet` 恢复 prefix forbid 状态，删除重复的 forbid 日志
vector。

## 19. 优化十四：BP singleton 强制传播

这是 07-26 相对 07-14 会改变逻辑节点统计的核心优化。

### 严格证书

如果 BP 返回：

```text
B = {e}
```

则 BP 的终止条件已经证明：

```text
所有能严格改善 incumbent 的 tour 都必须满足 x_e >= 1
```

因为 TSP 边变量 `x_e` 只能取 0 或 1，所以可推出：

```text
x_e = 1
```

### 07-14 行为

仍创建唯一的 `force e` 子节点：

- Created 增加；
- 进入下一层 search；
- Expanded 再统计一次；
- 执行父子状态切换。

### 07-26 行为

直接在当前逻辑节点：

1. force `e`；
2. 执行 degree、subtour 和 candidate propagation；
3. 增量修复当前 OneTree；
4. 继续 `search(..., count_node=false)`；
5. 不增加逻辑 depth，不重复统计 Expanded；
6. 返回时完整 rollback。

该优化没有删除可行改进 tour；它只是消除“数学上已经确定只有一个孩子”的包装
节点。

### 实验结果

MST 实验的 7 个正式实例汇总：

- Expanded 约减少 17.5%；
- Created 约减少 27.7%；
- singleton 单项 wall time 约改善 1.8%。

节点下降显著大于 wall time 改善，因为 force、候选传播、1-tree 修复和下一轮 BP
仍然必须执行，只是省去了逻辑节点包装和部分重复状态切换。

## 20. 优化十五：根 1-tree 树边 reduced-cost fixing

07-26 在进入 DFS 前测试根 OneTree 的未决树边 `e`：

1. 暂时 forbid `e`；
2. 计算该边的最轻合法 replacement；
3. 得到禁止 `e` 后的 replacement bound；
4. 若找不到 replacement，或该 bound 已无法严格改善 incumbent，则所有改进
   tour 都必须使用 `e`；
5. 将 `e` 永久固定为 `x_e=1`；
6. 所有 fixed-one 边同时生效后，只做一次候选过滤和一次根 OneTree rebuild。

内部 MST 边使用 fundamental cut replacement；根边使用独立的 root candidate
列表。浮点 delta 会加尺度化 roundoff guard，避免边界比较误固定。

验证构建会完整 rebuild forbid 后的根 OneTree，检查快速 replacement bound。

该优化只在严格证书成立时固定边。历史 7 个 singleton 正式实例的
`fixed_one=0`，所以那组节点下降完全来自 singleton 传播；在其他实例命中时，
根 fixing 会进一步减少候选和搜索空间。

### 21.1 相对 07-14-deg

10 个共同完成实例中：

- 每个实例都更快，时间下降约 34.33%～82.00%；
- 每个实例 Expanded 都更少，下降约 14.60%～30.09%；
- 汇总时间下降 80.93%；
- 汇总 Expanded 下降 18.93%；
- 汇总 Created 下降 29.50%。

这说明总收益同时来自：

- 07-20/07-26 热路径优化带来的单节点成本下降；
- BP singleton 带来的逻辑节点下降。

实例汇总：

- Expanded 下降 56.28%；
- Created 下降 64.83%。

相对 07_02 的大幅节点下降不能全部归因于 07-26 新增优化，还包含
`07_02 -> 07-14 BP degree` 的分支策略演进。

## 22. 为什么时间改善大于 Expanded 改善

相对 07-14-deg，汇总 Expanded 下降约 18.93%，但耗时下降约 80.93%。差异来自
大量不直接改变节点数的热路径优化：

- 候选 vector 不再逐层复制和 compact；
- OneTree 不再逐层复制；
- 删除候选不再随机写多套 active 状态；
- 边位置 O(1) 查询；
- MST cut 不再重建临时 DSU；
- replacement 直接使用 cut candidate 位图；
- `n <= 64` 的 component 和 forced membership 使用 machine word；
- available-degree infeasibility O(1)；
- 短 BranchSet 不分配 heap；
- 只检查 undo delta 或当前树边中的较小集合。

也就是说：

```text
总耗时
  = 逻辑搜索状态数量
  × 每次 BP / propagation / replacement / rollback 的平均成本
```

07-26 同时降低了这两个因子。

## 23. 正确性不变量

### 23.1 Candidate 状态

生产路径以 `candidate_bits` 为 active 真值，并要求：

- active bit 与当前 forced/forbidden 状态相容；
- undo 只记录实际发生的 `1 -> 0`；
- rollback 恢复精确的稳定 index；
- available degree 与 active incident 数一致。

### 23.2 OneTree 状态

每次 replacement 和 rollback 同步维护：

```text
edges
degree
cost
edge_index_in_tree
mst_adjacency_bits
```

### 23.3 Forced 状态

每次 force 和 rollback 同步维护：

```text
forced flag
forced degree
DSU parent/rank/component size
member bits 或 member vector
forced edge list
forced MST cost/count
```

### 23.4 Verification 构建

`TSP_VERIFY_INCREMENTAL_STATE` 会：

- 完整 rebuild 当前约束下的 OneTree；
- 比较可行性和成本；
- 验证动态 MST 位图；
- 验证边位置索引；
- 验证局部候选过滤没有漏删非法边；
- 重算 available degree；
- 检查 root fixing replacement；
- 检查 singleton propagation 后的增量树。

## 24. 尝试后未保留的优化

07-26 MST 实验明确回退了若干“节点更少但 wall time 更慢”的方案：

| 方案 | 结果 |
|---|---|
| 全候选 best-replacement cover | 约慢 7.1% |
| 只保留 replacement singleton fixing | 仍慢约 1.9% |
| 候选数不超过 2 才做 cover | 约慢 6.1% |
| 最大收益反向加边精简 B | 约慢 1.8% |
| 自适应完整 rebuild，阈值 2 | 约慢 23.4% |
| 自适应完整 rebuild，阈值 3 | 约慢 2.1% |
| 度违规主排序 | 约慢 6.3% |
| candidate undo 按 64-bit word 合并 | 约慢 0.8% |

关键经验是：

```text
不要为了发现 propagation 证书额外执行昂贵的 replacement 预扫描；
优先消费原 BP 已经产生的严格证书。
```

## 25. 当前仓库中的命名注意事项

当前 `FULLHKMST` 工作树的 CMake 中：

```cmake
tsp_add_solver(tsp_bb)
tsp_add_solver(tsp_bb_26_07_14_deg EXCLUDE_FROM_ALL)
```

两个目标都从当前工作树的同一份 `src/main.cpp` 和 `src/TspSolver.cpp` 构建，
且都不定义 min-edge/full-recompute 宏。因此：

- 目标名 `tsp_bb_26_07_14_deg` 不会自动固定到 `3131435`；
- 在当前 `FULLHKMST` 工作树重新构建，该目标会包含 07-14 之后的代码；
- 当前 `tsp_bb` 还包含 HKMST/FULLHKMST 路线的后续变化；
- 历史比较必须使用固定提交或缓存中明确的 solver key。

当前 `MST` 分支指向 `f36d206`；`07-20-MST` 归档指向较早的 `4619e84`。
二者不是同一版本。

## 26. 复现实验建议

若要重新测量完整的 `07-14-deg -> 07-26-MST` 差距，应：

1. 从 `3131435` 构建 07-14 基线；
2. 从 `f36d206` 构建 MST 候选版；
3. 使用相同编译器、Release flags 和硬件；
4. 固定实例、超时和 `--exact-max-n`；
5. 基线与候选逐轮交换运行顺序；
6. 同时报告 wall time、Created、Expanded、成本和 tour；
7. 对短实例报告多轮中位数或均值；
8. 不将 timeout 当作 0；
9. 不直接相加不同提交的局部提升百分比。
