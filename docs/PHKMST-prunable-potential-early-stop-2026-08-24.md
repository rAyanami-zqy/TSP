# PHKMST 可剪枝势证书早停

## 目标

减少 PHKMST 中已经不会改变搜索决策的势迭代。此前节点势更新只有在浮点
下界达到 incumbent、次梯度为零或数值异常时才停止；但对于安全整数成本
实例，`shouldPrune` 还能利用带舍入保护的整数下界：

```text
ceil(lower_bound - roundoff_tolerance) >= incumbent
```

一旦该条件成立，当前节点必然被下界剪枝，继续增强证书不会改变 DFS、BP、
候选状态或最终最优解。

## 实现

每轮 Prim 势评估保存当前最佳安全下界，并调用与正式搜索完全相同的
`shouldPrune`。证书已经足够剪枝时立即结束剩余 Polyak 迭代。非整数成本仍
沿用原有保守浮点判定，不放宽剪枝条件。

新增统计 `potential_updates_stopped_prunable`，记录尚有剩余轮次、但因证书
已经充分而提前结束的尝试数。该机制同时适用于临时证书和 persistent subtree
epoch 模式；后者被直接剪枝时本来就不会安装新 epoch。

## 九实例对照

配置：`subtree-adaptive`、gap 2%、epoch 层距 2、最多 16 轮、每轮预算
5000。基线为 PHKMST 提前结束改动前的同一提交，两组 Release 构建交错运行
五轮。

| 指标 | PHKMST 基线 | 可剪枝早停 | 变化 |
|---|---:|---:|---:|
| 势迭代总数 | 30,756 | 23,619 | -23.20% |
| 势更新时间中位数 | 0.294580 s | 0.276463 s | -6.15% |
| 整批 wall 中位数 | 1.12 s | 1.10 s | -1.79% |
| 提前结束尝试 | 0 | 2,790 | +2,790 |
| created | 292,940 | 292,940 | 0 |
| expanded | 201,129 | 201,129 | 0 |
| 更新尝试 | 3,441 | 3,441 | 0 |
| 直接剪枝 | 2,802 | 2,802 | 0 |
| epoch 重建 | 533 | 533 | 0 |

迭代数下降大于势更新时间下降，说明每次尝试固定支付的 forced-component、
active 邻接构建和临时数组初始化已经成为主要占比。下一步若继续优化势更新
内核，应优先减少这些固定预处理，而不是预测性跳过尚未评估的节点。

## 被否决的预测式规则

实验过“8 轮无提升即停止”和“失败后跨兄弟节点延长触发间隔”。九实例中有
380 次有效更新直到第 8 轮以后才首次改善，92 次直到第 12 轮以后才首次改善；
预测式规则会漏掉这些锚点，并显著放大 st70、rat99 和 eil101 的搜索树。因此
最终实现不保留固定探测轮数或跨节点失败退避，只采用已经能够证明不会改变
搜索决策的可剪枝早停。

## 验证

- CTest 4/4 通过；
- st70 回归测试明确覆盖可剪枝早停；
- 九个经典实例均返回已知最优值；
- 九实例的 created、expanded、直接剪枝和 epoch 重建计数与 PHKMST 基线一致。
