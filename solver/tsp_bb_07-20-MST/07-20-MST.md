## 当前实现

### 全局候选集与可逆状态

- `solve()` 只构造一份不可变、按权重排序的 `candidates_sorted_`。
- 使用 active bitset 和双向有序链维护当前候选集。
- 候选删除为 O(1)，通过 `CandidateUndo` 逆序恢复。
- 消除了 DFS 热路径中的 `prefix_candidates`、`child_candidates` 及候选数组 compact/erase/copy。

### 单棵可变 OneTree

- DFS 只维护一棵可变 `OneTree`。
- 树边交换记录到 `TreeUndo`，子节点返回时按 checkpoint 精确恢复。
- BP 前缀分支顺序重放树状态，不再为每个子节点复制完整 OneTree。
- 完整重建只保留为增量 replacement 失败时的冷路径。

### 局部候选过滤与 available degree

- forced DSU 维护可回滚的分量成员列表。
- force 后只处理以下候选：forced 边本身、forced degree 达到 2 的端点关联边，以及新合并 forced 分量产生的内部边。
- `available_degree_` 增量维护 forced degree 与 active candidate incidence 之和。
- `insufficient_degree_count_` 将度数可行性判断降为 O(1)。

### MST replacement 热路径

- MST 邻接关系使用按行存储的位图。
- DFS 邻接枚举使用编译器快速尾零位扫描。
- force 后只收集当前 OneTree 中 inactive 且非 forced 的树边。
- 仅对这些失效树边按全局 candidate rank 排序，避免排序本轮删除的全部候选。
- replacement edge 仍从有序 active candidate 链中查找，保持原搜索语义。

### Active incident 位图

- 每个顶点预生成不可变的 incident candidate 位图。
- 过滤时使用 `active_bits & incident_bits`，只枚举仍 active 的关联边。
- `deactivateCandidateByIndex` 直接按稳定 candidate index 删除，消除 `index -> edgeId -> rank -> index` 的往返转换。
- 位图状态沿用现有 candidate undo 回滚，不增加新的递归状态副本。

## 性能对比

以下为最新 active-incident 位图优化相对修改前最新版本的 user CPU 中位数。长实例交替运行 7 轮；短实例每批连续求解 20 次，交替运行 5 批。

| 实例 | 修改前 | 07-20-MST | 改善 |
|---|---:|---:|---:|
| gr17 | 0.63s | 0.56s | 11.1% |
| gr24 | 0.23s | 0.21s | 8.7% |
| fri26 | 0.48s | 0.43s | 10.4% |
| wi29 x20 | 0.66s | 0.63s | 4.5% |
| dj38 x20 | 0.27s | 0.26s | 3.7% |

在此之前，本分支还完成了 OneTree/候选撤销日志、局部过滤、快速位扫描和仅排序树内失效边等优化；每一阶段均以当时最新版本作为基线，未观察到参考实例回退。

## 从源码构建

```bash
git switch MST
git pull --ff-only
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target tsp_bb
ctest --test-dir build --output-on-failure
```

默认生成物为 `build/tsp_bb`。需要更新归档时，将对应平台的 Release 二进制复制到本目录：

```bash
cp build/tsp_bb solver/07-20-MST/tsp_bb
```
